Departmental Modernization

Transforming Provincial Irrigation Administration in Southern Sri Lanka

The Southern Provincial Irrigation Department (SPID), headquartered in Galle, manages vital water resources, flood protection infrastructure, and agricultural irrigation networks across the Southern Province.

The SPID File Management System v3.0.0 transitions traditional physical record rooms into an intelligent, synchronized digital platform. Engineering officers, administrative executives, and registry staff now collaborate with real-time file availability, automated priority-based queues, and exact physical shelf coordinates.

  • Unified records covering Galle, Matara, and Hambantota engineering divisions
  • Strict Row-Level Security (RLS) guaranteeing data confidentiality
  • Automated session watchdog preventing concurrent multi-window request storms

Document Lifecycle

How Departmental Files Are Handled

From initial registration to physical archival, every step follows official administrative protocol.

01

File Registration

Officer registers new scheme file with official File Code, project title, start/end dates, exact minute sheet count, and assigns physical Locker & Shelf position.

02

Digital Requisition

Authorized staff search the repository and submit a checkout request indicating the required duration and urgency level (High, Normal, or Low priority).

03

Admin Clearance

Registry administrators inspect competing claims, approve the checkout order, calculate the return deadline, and log the physical transfer in the digital ledger.

04

Safe Return & Audit

Upon completion, the physical file is verified for intact minute sheets, returned to its exact locker/shelf coordinate, and signed off in the audit repository.

Operational Assistance

Frequently Asked Questions

Answers to standard operating procedures and technical policies for SPID officers.

When multiple officers request the same irrigation file, the system ranks them by priority level (High, Normal, Low) and timestamp order. Administrators can review all pending competing claims simultaneously and award custody based on official departmental urgency.
Every file registration requires three specific coordinate attributes: Locker Number (e.g. LK-04), Shelf Unit (e.g. Shelf 02), and Position Depth (Front, Middle, or Back). This eliminates guesswork and enables archive assistants to retrieve the exact physical folder in under 30 seconds.
To prevent brute-force credential stuffing, the system triggers progressive lockouts. After repeated failed attempts, the account enters a timed lockout window with an on-screen countdown. If failed attempts persist, an administrator must manually verify and unlock the account via the Admin User Management panel.
Yes. Through the Staff Portal's "Your Requests" panel, officers can submit an online extension request detailing their proposed new return date and operational justification. The reviewing administrator receives an instant notification to approve or adjust the new deadline.
All records are protected by PostgreSQL Row-Level Security (RLS) policies within Supabase. Users can only browse and interact with files belonging to approved sections or public schemes. Internal audit logs record every file access and state change with non-repudiable officer attribution.
New employees complete the self-registration form with their official government email, staff ID, and assigned section. The account remains in 'Pending' status until verified and approved by a designated System Administrator.
